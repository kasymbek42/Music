# PRD — Song Analyzer (Разбор трека)

## Что это

Полностью клиентское браузерное SPA для музыкантов: загружаешь свой аудиофайл — получаешь
аккорды с временной шкалой, гитарные аппликатуры и разделение трека на инструменты (вокал /
барабаны / бас / прочее). Никакого backend, никакого сервера — всё работает прямо в браузере.
Хостинг — GitHub Pages.

**Live:** https://kasymbek42.github.io/Music/
**Репо:** https://github.com/kasymbek42/Music

---

## Целевой пользователь

Гитарист/музыкант, который хочет быстро разобрать чужую песню: узнать аккорды, посмотреть
аппликатуры, послушать партии по отдельности — без нотных редакторов, платных сервисов и
установки приложений.

## Текущее состояние (v1, реализовано)

### Флоу
1. **Загрузка файла** — drag-and-drop или клик. Форматы: mp3, wav, m4a, flac, ogg, aac.
   Файл никуда не отправляется, обработка локальная через Web Audio API.
2. **Экран анализа** — спиннер со статусом ("Читаем аудиофайл…" / "Распознаём аккорды…").
3. **Экран результатов:**
   - Имя файла + waveform (canvas, оранжевый цвет `#d98b3f`)
   - Панель аккордов: временная шкала чипов (кнопок) с меткой времени
   - Клик по чипу → подсвечивается нужная карточка аппликатуры
   - Панель аппликатур: SVG-схемы ладов для каждого уникального аккорда
   - Панель стемов: кнопка "Разделить на инструменты" → прогресс-бар → audio-плееры + ссылки на скачивание (drums/bass/other/vocals .wav)
   - Кнопка "Загрузить другой трек"

### Стек
- Vanilla JS (ES2020+), без фреймворков и сборщиков
- `onnxruntime-web@1.19.2` (CDN jsDelivr) — инференс ONNX в браузере через WASM
- HTDemucs ONNX (StemSplitio/htdemucs-onnx, Hugging Face, MIT) — модель разделения стемов
- `coi-serviceworker.js` — COOP/COEP полифилл (нужен для SharedArrayBuffer / многопоточного WASM на GitHub Pages)
- Статический хостинг GitHub Pages, ветка `master`, корень `/`

### Файловая структура
```
/
├── index.html               SPA, 3 экрана (upload / analyzing / results)
├── coi-serviceworker.js     COOP/COEP полифилл
├── css/
│   └── style.css
└── js/
    ├── audio-loader.js      File → AudioBuffer (Web Audio API)
    ├── chords.js            FFT + chroma + шаблонный матчинг → [{chord, startSec, endSec}]
    ├── guitar-chords.js     Словарь аппликатур + SVG-рендер
    ├── waveform.js          Отрисовка waveform на canvas
    ├── stem-separation.js   HTDemucs ONNX, overlap-add чанкинг, WAV-энкодер
    └── app.js               Оркестрация состояния и экранов
```

### Алгоритм распознавания аккордов (chords.js)
- FFT размером 4096, шаг 2048 сэмплов
- Chroma-вектор (12 полутонов) из спектральных бинов (диапазон A0–C8)
- Косинусное сходство с шаблонами: maj / min / 7 / maj7 / m7 / dim / aug / sus2 / sus4 × 12 тональностей = 108 шаблонов
- Порог тишины: 50% от 10-го перцентиля энергии
- Сглаживание: скользящая мода, окно 8 кадров
- Склейка коротких сегментов < 0.5 с

### Разделение стемов (stem-separation.js)
- Модель скачивается с Hugging Face (~80–150 МБ), кэшируется в Cache Storage API
- Overlap-add чанкинг: сегменты по 343 980 сэмплов (≈7.8 с при 44.1 кГц), перекрытие 8192
- Линейный кросс-фейд на стыках
- Требует 44 100 Гц (модель не ресемплирует сама)
- Выход: drums / bass / other / vocals → WAV Blob (16-bit PCM стерео)

## Известные ограничения

| Ограничение | Причина |
|---|---|
| Только свой файл, нет поиска по названию | Нет backend; стриминг требует серверного ключа |
| DRM-файлы (Apple Music) не работают | Браузер не может расшифровать DRM |
| Нотный стан не реализован | Полифоническая транскрипция сложнее chroma-подхода |
| Стемы могут занять несколько минут | CPU-инференс через WASM без GPU |
| Аккорды неточны на джазе/искажениях | Классический алгоритм, не нейросеть |
| При первом визите — автоперезагрузка | coi-serviceworker включает COOP/COEP заголовки |
| Только 44 100 Гц для стемов | Ограничение модели HTDemucs |

## Дорожная карта (что делать дальше)

### P0 — Критично / быстрый выигрыш
- [ ] **Ресемплинг до 44 100 Гц** — сейчас `separateStems` бросает ошибку если sampleRate ≠ 44100.
  Нужно добавить ресемплинг через `OfflineAudioContext` в `audio-loader.js` или в начале стема.
- [ ] **Индикатор "модель уже кэширована"** — показывать иконку/бейдж "модель готова" между визитами,
  чтобы пользователь знал, что повторной загрузки не будет.

### P1 — Важные улучшения
- [ ] **WebGPU execution provider** — в Chrome/Edge с WebGPU включить `executionProviders: ["webgpu", "wasm"]`
  для ускорения инференса в 5–10× на поддерживаемых устройствах.
- [ ] **6-стемовая модель** — опция переключения на `StemSplitio/htdemucs-6s-onnx` (+гитара, +пианино).
- [ ] **Улучшение распознавания аккордов** — заменить/дополнить chroma-алгоритм нейросетевой моделью
  (например, портированный `chord-recognition` ONNX). Особенно важно для джаза и сложной гармонии.
- [ ] **Воспроизведение с синхронизацией аккордов** — `<audio>`-плеер для исходного трека с автоподсветкой
  текущего аккорда по `timeupdate`.

### P2 — Расширения
- [ ] **Нотный стан** — отображение распознанных нот/аккордов в стандартной нотации (VexFlow или аналог).
- [ ] **BPM / тональность** — автоопределение темпа и тональности трека.
- [ ] **Транспозиция аппликатур** — кнопки +/− полутон, капо-калькулятор.
- [ ] **Экспорт аккордов** — скачать последовательность как .txt / .pdf / ChordPro.
- [ ] **PWA / офлайн** — service worker для офлайн-работы после первой загрузки (модель уже кэшируется).

## Технические решения, которые стоит сохранить

1. **coi-serviceworker** — не трогать; без него WASM-многопоток не работает на статическом хостинге.
2. **Cache Storage для модели** — уже реализовано, не ломать при рефакторинге.
3. **Overlap-add чанкинг** — критичен для длинных треков; без него браузер падает по памяти.
4. **Vanilla JS без сборщика** — намеренно, чтобы деплой оставался `git push` без CI.
