# Разбор трека — аккорды, аппликатуры, партии инструментов

Полностью клиентское (browser-only) одностраничное приложение: **без backend, без базы
данных, без сервера**. Всё — загрузка файла, анализ аккордов, разделение на инструменты —
происходит в браузере пользователя. Подходит для хостинга на **GitHub Pages**.

## Что делает приложение

1. **Загрузка своего аудиофайла** (mp3, wav, m4a, flac, ogg) — drag-and-drop или выбор файла.
   Файл не отправляется никуда — обработка локальная, через Web Audio API.
2. **Распознавание аккордов** — chroma-анализ на чистом JS (FFT + сопоставление с шаблонами
   аккордов), с отображением последовательности по времени трека.
3. **Гитарные аппликатуры** — для каждого распознанного аккорда показывается схема лада
   (словарь типовых открытых позиций + SVG-рендер).
4. **Разделение на инструменты (стемы)** — опциональная тяжёлая операция: нейросеть HTDemucs,
   портированная в формат ONNX, выполняется прямо в браузере через `onnxruntime-web` (WASM).
   Разделяет трек на 4 партии: вокал, барабаны, бас, прочее.

## Что НЕ делает приложение (и почему)

- **Не ищет и не скачивает треки по названию.** Без собственного backend-сервера нет
  легального и технического способа получить аудио чужого трека по имени — стриминговые
  сервисы либо не отдают сырой звук вообще, либо требуют сервер-посредник с ключами API.
  Загрузка собственного файла — единственный поддерживаемый сценарий.
- **Не работает с защищёнными DRM файлами** (стандартная загрузка из Apple Music) — это
  технический запрет на расшифровку DRM-контента, а не ограничение кода.
- **Не транскрибирует в ноты на нотном стане** — в этой версии оставлены только аккорды
  и аппликатуры; транскрипция полифонического аудио в ноты намного сложнее и пока не
  реализована в browser-only варианте.

## Технические ограничения, о которых стоит знать

- **Разделение на стемы — медленная операция.** Модель (~80–150 МБ) скачивается при первом
  использовании. Сам инференс на CPU через WASM может занимать от десятков секунд до
  нескольких минут на трек, в зависимости от длины файла и мощности устройства. Это
  осознанный трейд-офф за полностью клиентскую работу без сервера.
- **Распознавание аккордов** — классический алгоритм (chroma + шаблоны), не нейросеть.
  Хорошо работает на поп/рок-музыке с понятной гармонией; может ошибаться на джазе,
  сложных модуляциях, сильно искажённых тембрах.
- **Аппликатуры** — это словарь стандартных открытых позиций, а не результат анализа звука.
  Один аккорд можно сыграть разными способами; показывается самый распространённый вариант.
- **Кросс-браузерная изоляция (COOP/COEP).** Чтобы `onnxruntime-web` мог использовать
  многопоточный WASM, нужны специальные HTTP-заголовки, которые GitHub Pages не позволяет
  настраивать напрямую. Решается через `coi-serviceworker.js` — service worker, который
  подставляет эти заголовки на лету (общеизвестный паттерн для статического хостинга).
  Из-за этого при первом визите страница один раз перезагрузится автоматически.

## Структура проекта

```
song-analyzer-pages/
├── index.html                  единственная страница приложения (SPA)
├── coi-serviceworker.js        COOP/COEP полифилл для GitHub Pages (MIT, gzuidhof/coi-serviceworker)
├── css/
│   └── style.css
└── js/
    ├── audio-loader.js         File -> AudioBuffer через Web Audio API
    ├── chords.js                распознавание аккордов (FFT + chroma + шаблоны)
    ├── guitar-chords.js         словарь аппликатур + рендер SVG-схем
    ├── stem-separation.js       onnxruntime-web + HTDemucs ONNX, overlap-add чанкинг
    ├── waveform.js               отрисовка формы волны на canvas
    └── app.js                   оркестрация экранов и состояния приложения
```

## Деплой на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите туда содержимое этой папки (структуру файлов
   нужно сохранить как есть — `index.html` должен быть в корне).
2. В настройках репозитория откройте **Settings → Pages**, выберите источник
   **Deploy from a branch**, ветку `main` (или `master`), папку `/ (root)`.
3. Через минуту-две сайт будет доступен по адресу
   `https://<ваш-username>.github.io/<имя-репозитория>/`.
4. Откройте сайт — при первом визите страница автоматически перезагрузится один раз
   (это работа `coi-serviceworker.js`, включающего нужные заголовки изоляции).

Никаких build-шагов, серверов, переменных окружения или баз данных не требуется —
это обычные статические файлы.

## Используемая модель и лицензии

- **HTDemucs ONNX**: [`StemSplitio/htdemucs-onnx`](https://huggingface.co/StemSplitio/htdemucs-onnx)
  на Hugging Face — однофайловый ONNX-экспорт модели HTDemucs (Meta AI), MIT license.
  Оригинальная архитектура: Rouard, Massa, Défossez, "Hybrid Transformers for Music Source
  Separation", ICASSP 2023.
- **onnxruntime-web** — Microsoft, MIT license, подключается через CDN (jsDelivr).
- **coi-serviceworker.js** — Guido Zuidhof и контрибьюторы, MIT license,
  [gzuidhof/coi-serviceworker](https://github.com/gzuidhof/coi-serviceworker). Файл включён
  в проект без изменений.

## Возможные доработки

- Кнопка повторного запуска без перекачивания модели (уже кэшируется через Cache Storage
  API, но можно добавить явный индикатор "модель готова" между визитами).
- WebGPU execution provider вместо WASM для ускорения на поддерживающих браузерах
  (Chrome/Edge с включённым WebGPU).
- 6-стемовая модель (+ гитара, фortepиано) как опция — `StemSplitio/htdemucs-6s-onnx`.
- Отображение распознанных аккордов на стандартном нотном стане, не только аппликатуры.
